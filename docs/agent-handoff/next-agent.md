## Decisions and configuration

- Classification records are pair-level overlays (ADR-0009): one KU can
  join multiple differently-typed pairs, so per-KU overlap columns stay
  NULL; classifications live in `state/classifications/*.jsonl`
  (append-only once committed) and are applied to the derived registry via
  `vu kureg-apply-overlap`.
- Classification evidence MUST be byte-exact quotes verified inside the
  referenced KU excerpt (`scripts/ext003_classifications.py` enforces this;
  term counts are never classification evidence).
- Dispositions wait for synthesis output (all KUs stay Unaccounted).
- Pinned vault-ids: `ai-course` and `master-ai` (unchanged; changing them
  would mint different source ids and KU ids).
- Heading/construct detection authority: `mdextract.extract_structure_text`
  (CAP-003) — never naive `#` regex.
- Task-queue schema note: the work-commit hash field is `commit`.
- Batch naming: `<sequence>-<task-id>-<scope>.jsonl`; classification
  batches: `<sequence>-<task-id>-<scope>-overlap.jsonl`.
- Term maps: `state/term-maps/<domain>-v<N>.json`, built from ACTUAL batch
  content (not topic lists); `_`-prefixed keys are documentation and
  ignored by the loader.
